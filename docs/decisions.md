# Entscheidungen

Mit dem Benutzer festgelegte Entscheidungen. Sie gehen dem Implementierungsplan [NETEX_EXPLORER_IMPLEMENTATION_PLAN.md](../NETEX_EXPLORER_IMPLEMENTATION_PLAN.md) vor, solange dieser nicht überarbeitet ist.

## Festgelegt

| Datum | Thema | Entscheidung |
|---|---|---|
| 30.10.2026 | Umfang Profile | Nur Schweizer NeTEx-Definitionen. Andere europäische Profile (Nordic, EPIP, FR, DE …) sind kein Thema; keine Adapter dafür. |
| 30.10.2026 | Mehrere CH-Versionen | Mehrere CH-Guide-Versionen parallel über versionierte Adapter, inklusive Guides in Entwicklung. Ein generischer Explorer (ohne fachliche Deutung) bleibt als Rückfallebene. |
| 30.10.2026 | Erste Zielversion | Neueste Version des CH-Profils 2.0 (Entwurf, NeTEx 2.1), Branch `next` des Guide-Repos, abgebildet mit den dort bereitgestellten Dateien (Beispiele, Templates, Schematron, XSD). Details: [research/guide-2.0.md](research/guide-2.0.md). |
| 30.10.2026 | Guide-Dateien beziehen | Nicht ins Projekt kopieren. Ein Skript lädt sie von GitHub auf einem festen Commit (Commit-Archiv; kein Git nötig, damit auch unter Windows). Das XSD-Submodul ist im Archiv **nicht** enthalten und wird separat von NeTEx-CEN auf dem im Guide gepinnten Commit geladen (Stand `b7ac158`: `xsd` → `73b337e`). Ein Commit-Wechsel ist ein bewusster Schritt mit Testlauf (siehe „Guide-Update“); die UI zeigt den Stand. Ablage: Verweis in `netexRealisationGuideSwitzerland.lock.json` (versioniert), Dateien in `../netexRealisationGuideSwitzerland/<commit>/` (nicht versioniert, ausserhalb des Projekts). |
| 30.10.2026 | Guide-Update | Fester Stand bleibt (in `netexRealisationGuideSwitzerland.lock.json`). Ein Update wird nicht automatisch geholt, muss aber **einfach** sein: **ein Befehl** (`scripts/update-guide.sh` / `.ps1`), der (1) den neuesten Commit von `next` und den zugehörigen XSD-Commit ermittelt, (2) die Dateien in `../netexRealisationGuideSwitzerland/<commit>/` lädt, (3) einen Bericht über geänderte Guide-Dateien zeigt (neu, geändert, entfernt; Beispiele, Templates, Schematron, XSD), (4) die Tests gegen den neuen Stand ausführt und (5) bei grünen Tests den Lock auf den neuen Commit setzt. Bei roten Tests bleibt der alte Stand aktiv, der Bericht zeigt die Ursache. Eine Schaltfläche in der lokalen Oberfläche ist optional und später möglich. |
| 30.10.2026 | Kennzeichnung Entwurf | Entwurfs-Adapter in der UI als „in Entwicklung“ mit Guide-Commit anzeigen. Prüfungen gegen Entwürfe nie als „gültig“, sondern als „geprüft gegen Entwurf <Commit>“. |
| 30.10.2026 | Grosse Lieferungen zurückgestellt | Zuerst nur die kleinen 2.0-Dateien des Guide-Repos. Die 1.10-Lieferung `../netex-files/` (12 GB) und grosse Lieferungen generell kommen später. Die Entscheide zu Import und Index-Umfang unten gelten erst ab dann. Bis dahin bleibt die Architektur so, dass grosse Mengen später möglich sind (Streaming, kein vollständiges Laden), wird aber nicht darauf optimiert oder damit getestet. |
| 30.10.2026 | Import *(ab grossen Lieferungen)* | Primär aus einem konfigurierten, freigegebenen lokalen Ordner bzw. ZIP-Pfad. Browser-Upload nur zusätzlich für kleine Dateien. |
| 30.10.2026 | Umfang des Index *(ab grossen Lieferungen)* | Ganze Lieferung indexieren (leichtgewichtiger Index); Details bei Bedarf aus der Originaldatei lesen. |
| 30.10.2026 | Plattformen | macOS **und** Windows: `start.sh` und `start.ps1`; Pfade, Dateisperren und Encodings auf beiden testen. |
| 30.10.2026 | Stack (aus Plan bestätigt, angepasst durch die Entscheide unten) | React + TypeScript + Vite, Cytoscape.js, CodeMirror 6, Python-Kern (lokal unter FastAPI, im Browser unter Pyodide), SQLite, Importjob als Hintergrundprozess (kein Celery/Redis), pytest/Vitest/Playwright. |
| 30.10.2026 | XML-Parser | **pyexpat** (Python-Standardbibliothek) für das Einlesen und Indexieren: exakte Position je Element (Byte, Zeile, Spalte). **lxml** nur für XSD- und Schematron-Prüfung. Begründung: Die Position in der Datei ist Kern der Herkunftsanzeige; ein späterer Parserwechsel würde Index und Tests betreffen. Mehraufwand: eigene Verschachtelungs- und Namespace-Behandlung. |
| 30.10.2026 | XML-Pfad im Index | Pfadform (ohne Positionsnummern) einmal in einer Pfad-Tabelle speichern; jedes Objekt verweist darauf und speichert seine Position (Datei, Byte-Offset, Zeile, Spalte) sowie den Frame. Den vollständigen Pfad mit Positionsnummern (z. B. `ServiceJourney[3]`) beim Anzeigen berechnen. Keine XPath-Zeichenkette pro Objekt. |
| 30.10.2026 | Betriebsformen | **Lokal** (wie im Plan) **plus einfachere Webversion als statische Seite**. In der Webversion findet die Verarbeitung vollständig im Browser statt (Python über **Pyodide**; pyexpat und lxml 6.1.3 dort verfügbar). Kein Server, kein Upload; Dateien verlassen den Rechner des Nutzers nicht. Zielgruppe der Webversion: Guide-Dateien und kleinere Lieferungen; grosse Lieferungen nur lokal. Folge: Der Kern (Einlesen, Index, Referenzen, Projektion, Herkunft) wird als reines Python-Paket ohne Server-Abhängigkeiten gebaut, das unter FastAPI und unter Pyodide läuft; die Oberfläche greift über eine austauschbare Datenschicht zu (HTTP lokal, direkter Aufruf im Browser). Keine gehostete Server-Variante. |
| 30.10.2026 | XML-Anzeige | **CodeMirror 6** statt Monaco: schreibgeschützte Ausschnitte mit exakter Bereichsmarkierung. Begründung: leicht und einfach einzubinden, wichtig für die Webversion (Download-Grösse), gleiche Komponente lokal und im Browser. |
| 30.10.2026 | Veröffentlichung Webversion | Zielgruppe und Ort noch offen, wird später entschieden. Die Webversion wird so gebaut, dass sie als reine statische Dateien überall läuft: relative Pfade, keine serverseitige Logik, keine Annahme über Domain oder Unterpfad (z. B. funktioniert sowohl unter `/` als auch unter `/netex-explorer/`). |
| 30.10.2026 | Guide-Dateien in der Webversion | **Mit der Webversion ausliefern:** Der Build lädt die Guide-Dateien und die XSD auf dem festen Commit (gleiches Skript wie lokal) und packt sie in die statische Seite. Funktioniert ohne Internet und ohne GitHub-Abhängigkeit zur Laufzeit. **Auflage:** Das Guide-Repo nennt keine Lizenz. Vor einer Veröffentlichung, die über einen privaten Kreis hinausgeht, die Weiterverteilung klären (Kontakt laut Repo: info.fachbus@sbb.ch). Die XSD von NeTEx-CEN hat eine eigene Lizenz, ebenfalls prüfen. Nutzer können zusätzlich eigene Dateien öffnen. |
| 30.10.2026 | Speicher in der Webversion | Index (SQLite unter Pyodide) **nur im Arbeitsspeicher** für die laufende Sitzung; beim Neuladen werden die Dateien neu eingelesen. Keine Daten bleiben im Browser liegen. Dauerhafte Speicherung (OPFS/IndexedDB) ist später nachrüstbar, ohne den Kern zu ändern. |
| 30.10.2026 | Ordnerstruktur | Klare Trennung von eigenem Code und fremdem Inhalt auf oberster Ebene (Vorschlag des Benutzers):<br>`NeTEx-Viewer/` = Sammelordner, nicht versioniert<br>`├── netexRealisationGuideSwitzerland/<commit>/` = Guide-Dateien + XSD, nur durch `update-guide` befüllt, nie von Hand ändern<br>`├── netex-files/` = Lieferdaten<br>`└── netex-explorer/` = eigenes Projekt und eigenes Git-Repository: `CLAUDE.md`, `README.md`, Plan, `netexRealisationGuideSwitzerland.lock.json`, `app/` (`core/`, `server/`, `frontend/`), `scripts/`, `fixtures/`, `docs/`.<br>Der Pfad zu `netexRealisationGuideSwitzerland` und `netex-files` ist konfigurierbar, Standard `../netexRealisationGuideSwitzerland` bzw. `../netex-files`; `update-guide` legt den Guide-Ordner bei Bedarf an. Ersetzt die Struktur `netex-explorer-ch/` aus Plan-Abschnitt 12. |
| 30.10.2026 | Lieferdaten und LLM | Grosse Lieferungen nicht an das LLM senden; nur lokal per Skript auswerten. Siehe Arbeitsregeln in [CLAUDE.md](../CLAUDE.md). |
